# Wennera Assistant

Telegram-бот с Mini App для личного ассистента: профиль пользователя, заявки на исправление багов, заказы разработки и сообщения владельцу.

## Возможности

- черно-серый неоновый Mini App с плавными анимациями;
- подтвержденная авторизация через `Telegram.WebApp.initData`;
- SQLite-база в каталоге `data/`;
- заявки на баги с прикреплением изображения, видео или файла;
- заказ бота с произвольным бюджетом от 2500 рублей;
- история заявок и заказов пользователя;
- уведомления владельцу через Telegram Bot API;
- AI-ответы на сообщения в чате с ботом (через OpenAI-compatible API);
- Telegram Business-подключение для ответов в выбранных личных чатах от имени аккаунта;
- личные команды владельца с префиксом `*` и проверкой Telegram ID;
- проверка доступности приложения и настраиваемых ботов/сервисов;
- поддержка Telegram Premium custom emoji при заданном `PREMIUM_EMOJI_ID`;
- запуск через inline-кнопку и menu button.

## Запуск

1. Установите Node.js 20+.
2. Выполните `npm install`.
3. Скопируйте `.env.example` в `.env` и заполните значения.
4. Запустите `npm start`.

Без `BOT_TOKEN` приложение запускается как публичный preview для проверки интерфейса. Бот и серверная авторизация включаются после добавления токена.

## Переменные окружения

`BOT_TOKEN` и `OWNER_TELEGRAM_ID` задают бота и владельца; по умолчанию используется ID `7288555779`. ID обычных пользователей добавлять вручную не нужно: Mini App автоматически получает и сохраняет его из проверенного Telegram `initData`. В production задайте `APP_URL` как публичный HTTPS-адрес, совпадающий с доменом, зарегистрированным в BotFather; HTTP и localhost для Telegram Web App-кнопок не используются. Секреты не храните в репозитории.

Без явного Business-подключения бот не имеет доступа к личным перепискам владельца. Публичная карточка заполняется безопасными переменными `OWNER_*`, а не попыткой читать личный аккаунт.

## AI-ответы и Business

Чтобы бот отвечал пользователям автоматически, задайте `AI_API_KEY`, `AI_MODEL` и при необходимости `AI_BASE_URL` для OpenAI-compatible endpoint. Сообщения пользователей будут отправляться выбранному AI-провайдеру; без ключа бот отправит уведомление владельцу и ответит стандартным сообщением.

Чтобы получать сообщения из личных чатов аккаунта, включите Business Mode для бота в настройках BotFather, затем в Telegram откройте **Настройки → Telegram для бизнеса → Чат-боты**, выберите этого бота и подключите нужные чаты. Владелец по умолчанию получает имя, username, ID и текст входящего сообщения. Чтобы бот мог отвечать, дополнительно выдайте право `can_reply`; без него уведомления продолжат приходить, но кнопка ответа и автоответ отключены. Задайте `BUSINESS_NOTIFICATIONS=false`, чтобы отключить уведомления. Для ручного ответа можно использовать `*bizreply <telegram_id|@username> <текст>`; доступная связь запоминается процессом после входящего сообщения.

Бот не может читать обычные личные переписки аккаунта без Business-подключения. Mini App остаётся доступным через `/start`, кнопку меню, `*app` и пользовательские заявки.

## Команды владельца

Команды начинаются с `*` и доступны только Telegram ID владельца. Отправляй их в личный чат с ботом; это не тот же чат, что Business-переписка с человеком. Основные: `*help`, `*status`, `*bots`, `*uptime`, `*ping`, `*id`, `*app`, `*say <telegram_id|@username> <текст>`, `*bizreply <telegram_id|@username> <текст>`, `*anketa` и `*anketa send [id|@username]`. Username разрешается только для пользователя, который уже писал боту или в подключённый Business-чат. `*anketa` создавай в личном чате бота; `*анкета` также работает. `*help` в группах отправляет список в личку владельцу. `*say` и `*anketa send` отправляют через активный Business-диалог, если он есть; иначе пользователь должен уже открыть обычного бота и нажать /start. При включённом Privacy Mode в группе укажи бота в команде, например `@<bot_username> *help` или `*help@<bot_username>`; без упоминания Telegram доставляет боту меньше типов сообщений, для чего нужно добавить его администратором или отключить Privacy Mode и заново добавить в группу. Командные сообщения другим участникам не отвечаются.

Входящие стандартные медиа-сообщения в личном чате пересылаются владельцу, ответ на пересланное сообщение отправляется исходному пользователю. Для Business-медиа копируются доступные типы по `file_id`. Ограничения Telegram для защищённых и некоторых платных/служебных сообщений остаются в силе.

`*status` показывает состояние этого приложения, Telegram Bot API и внешних health-check адресов. Bothost не предоставляет приложению сведения о других процессах автоматически. Для проверки других ботов задайте `BOT_HEALTHCHECKS` как JSON-массив публичных URL, отвечающих HTTP 2xx, например:

```env
BOT_HEALTHCHECKS=[{"name":"shop-bot","url":"https://example.com/healthz"}]
```

Сервер этого проекта предоставляет `/healthz`. Для custom emoji укажите ID из Telegram custom emoji pack в `PREMIUM_EMOJI_ID` и соответствующий обычный emoji в `PREMIUM_EMOJI_ALT`. Отправка custom emoji ограничена правилами Telegram: Premium у владельца бота либо покупка дополнительных usernames бота через Fragment.
